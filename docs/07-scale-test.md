# 規模測試：語料放大五倍會發生什麼（T37）

> 執行日期：2026-09-02。所有數字都是實測。

在決定要不要把三十幾個版本公告全部匯入之前，先用五個版本量一次。目的不是涵蓋
範圍，是取得「規模上升時檢索怎麼變」的資料——那是先前完全沒有的東西。

## 1. 做了什麼

匯入 5.1、5.2、5.3、5.4、5.5 五份版本公告，章節 locator 由標題自動產生
（每個標題一節，`end` 指向下一個標題）。

| | 之前 | 之後 |
|---|---:|---:|
| 來源文件 | 9 | 14 |
| 切塊 | 18 | **89** |
| 索引建立時間 | — | 9.3 秒 |
| 68 題評估耗時 | — | 2 分 14 秒 |

## 2. 沒有變差的部分

三項機器指標在 89 個切塊下完全不變：

| 準則 | 18 切塊 | 89 切塊 |
|---|---:|---:|
| Retrieval Recall@5 | 100% (58/58) | **100% (58/58)** |
| 無資料正確拒答率 | 100% (10/10) | **100% (10/10)** |
| 非拒答答案附來源率 | 100% (58/58) | **100% (58/58)** |

退回模板的仍然是同樣兩題。守門案例也都還成立：

- 「納塔的火神是誰？」→ `insufficient_evidence` 拒答、0 筆引用
- 「迪盧克是什麼元素？」（語料沒有的實體）→ 拒答

## 3. 變差的部分，以及一個不能再迴避的結論

### 3.1 相似度門檻的分離性消失了

先前 `DOCUMENT_MIN_SCORE` 之所以能設，是因為可回答的題目與語料答不出來的題目在
分數上分得開。放大之後不成立：

| | 18 切塊（T36） | 89 切塊（本次） |
|---|---|---|
| 可回答題的分數範圍 | 0.532 – 0.795 | **0.438 – 0.712** |
| 「納塔的火神是誰？」（答不出來） | 0.410 | **0.504** |
| 兩者是否分得開 | 是，間隙約 0.12 | **否，完全重疊** |

答不出來的那題現在得 0.504，落在可回答題目的區間**中間**。

**沒有任何門檻值能同時保住所有可回答的題目、又擋掉那一題。** 調高會犧牲
Recall，調低沒有意義。

這不是參數沒調好，是**這個機制到頂了**：語料越大，最近的不相關切塊就越接近最難
的相關切塊。門檻能擋住的只有「明顯在講別件事」，而那個空間隨資料量縮小。

### 3.2 那為什麼「納塔的火神是誰？」還是拒答了

因為擋住它的**已經不是門檻**，是 [`03-system-design.md` §9.3.1](03-system-design.md)
那個檢查：模型讀完證據後自己說「證據中沒有提到」，系統把那句話當成拒答而不是答案。

換句話說，目前系統在這件事上的正確行為**完全依賴模型自述**。模型沒察覺的時候，
沒有任何東西會發現。

### 3.3 版本總覽的答案品質掉了

T34 讓版本總覽取整份公告。在人工挑過章節的 5.0／2.1 上，那產生了條理分明的答案。
自動產生 locator、涵蓋整份公告（13–18 節）之後，答案開頭變成瑣事：

- 「5.3版本更新了哪些內容？」→ 開頭是**胡桃的語音新增**
- 「5.5版本新增了什麼角色？」→ 開頭是**信件珍藏盒增加搜尋功能**

模型拿到 9000 字、十幾節等權重的內容，就照著看到的順序寫。整份公告餵進去解決了
「證據不足」，但沒有解決「哪一段才是讀者要的」。

`versionDocumentMaxChunks` 目前是 24，本次最大的 5.5 是 18 節，還沒觸頂——所以
這個問題**不是上限擋掉的，是上限還沒擋到**。

## 4. 結論與建議

1. **不要調門檻。** 沒有可用的值，本文件 §3.1 是證據。
2. **把門檻的定位改寫。** 它是便宜的第一道過濾，不是正確性的保證——
   `03-system-design.md` §9.3 目前的寫法高估了它。
3. **[#65](https://github.com/frobel0520/Genshin-Impact-RAG-Helper/issues/65)
   （證據涵蓋度檢查）從「值得做」變成「擋在路上」。** 在它做完之前，
   繼續灌資料會讓系統在已經量到的那個方向上變差。
4. **版本總覽需要章節選擇，不是全取。** 這是 T34 的下一步，也是 §3.3 的直接後果。

### 這批資料要不要留

留著，語料就從 18 個切塊變成 89 個，而剛完成的 58 題評分描述的是 18 個切塊的系統，
會立刻失效。

**建議先不要留**：先做 #65，再把資料加回來，那時候才有東西能在資料變多時保護正確性。
本文件的量測結果不會因為資料被移除而失效——數字已經在這裡了。

——自動切出來的十幾節等權重，模型會照順序寫而不是照重要性寫。加回來的時候應該
連同章節選擇一起處理，而不是重複這次的作法。
