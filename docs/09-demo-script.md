# Demo 腳本：10 分鐘

> 本腳本的預期輸出來自 2026-09-02 的 E2E 紀錄（dataset `5c49fb1e6fc577c1`），
> 與 [`04-mvp-release-gate.md`](04-mvp-release-gate.md) §5 同一份。
> **Demo 前務必重跑一次確認**，見 §5 的檢查清單。

## 0. 開場一句話

> 「這是一個繁體中文的《原神》知識助手。它跟一般聊天機器人的差別不在答得多好，
> 在**答不出來的時候會說答不出來**——而且那件事是量化過的。」

不要開場就講技術棧。先讓對方看到拒答，再回頭講架構。

## 1. 五個問題，照這個順序打

順序是設計過的：先建立信任（拒答），再展示能力（回答），最後展示誠實（uncertain）。

| # | 問題 | 預期 | 你要講的一句話 |
|---|---|---|---|
| 1 | 雷電將軍該配什麼隊伍？ | `refused` / `out_of_scope` / 0 引用 | 「配隊建議在 MVP 範圍外，寫在計畫書 §4.2。它不是答不出來，是**知道自己不該答**。」 |
| 2 | 迪盧克是什麼元素？ | `refused` / `insufficient_evidence` / 0 引用 | 「迪盧克不在語料裡。一般模型會直接用權重裡的知識回答『火』——**答對了，但沒有依據**。這個系統拒答。」 |
| 3 | 納塔的火神是誰？ | `refused` / `insufficient_evidence` / 0 引用 | 「這題最有意思，等一下回來講。」（見 §2） |
| 4 | 5.0版本更新了哪些內容？ | `answered` / hoyolab 引用 | 「版本總覽會取整份公告，不是取最相似的幾段——那是 T34 修掉的一個缺陷。」 |
| 5 | 瑪拉妮是什麼元素？ | `uncertain` / `version_unknown` / hoyolab + genshin-db 兩個引用 | 「答案是對的，但標成 uncertain：genshin-db 描述的是**當前遊戲**、不帶版本，所以系統不宣稱它適用某個版本。兩個來源都附上了。」 |

第 5 題是整場最值得停下來的一格：**兩個不同來源都走到了同一個答案，而系統標示了它不知道的部分。**

## 2. 第 3 題的故事（準備好被問「為什麼這題有意思」）

「納塔的火神是誰？」在語料裡答不出來，但它**被拒答的理由換過一次**：

1. 一開始是相似度門檻擋掉的（0.410，低於門檻）。
2. 語料放大到 89 個切塊之後，它變成 0.504，**落在可回答題目 0.438–0.712 的區間中間**——門檻擋不住了，而且沒有任何門檻值能同時保住所有可回答的題目又擋掉它。
3. 現在擋住它的是另一道檢查：模型讀完證據自己說「證據中沒有提到」，系統把那句話判成拒答而不是答案。

> 「這件事我寫在 `docs/07-scale-test.md`。結論是**相似度門檻這個機制到頂了**——
> 語料越大，最近的不相關切塊就越接近最難的相關切塊。這不是參數沒調好。」

這段是整個 demo 裡最能展示「會量、敢寫負面結果」的部分。

## 3. 打開哪幾個檔案

被問到實作時，照這個順序開，不要一次全開：

1. [`docs/04-mvp-release-gate.md`](04-mvp-release-gate.md) — 五項指標與 68 題的結果
2. [`src/generation/answer-grounding.js`](../src/generation/answer-grounding.js) — 逐字姓名檢查：答案裡「引號括起來」或「單獨成為列表項」的名字，必須逐字出現在證據裡，否則整段退回引用版模板
3. [`docs/07-scale-test.md`](../docs/07-scale-test.md) §3.1 — 門檻到頂的那張表
4. [`src/README.md`](../src/README.md) — 模組邊界，由 `scripts/check-boundaries.js` 強制

姓名檢查值得講細節：**「蓋石山」**。模型把「踞石山」寫錯成「蓋石山」，每一次都錯同一個字，而它會帶著引用送到讀者面前。現在這種答案會退回模板。

## 4. 三個一定會被問到的問題

| 問題 | 一句話回答 |
|---|---|
| 「回答正確率 96.6% 是誰量的？」 | 「機器評分，**沒有人簽署**——而且評分的模型就是寫答案的模型。這件事寫在 gate 文件跟 README 裡，那兩項指標標成未簽署而不是綠燈。」 |
| 「語料只有 9 份文件會不會太少？」 | 「會。它是一條可展示的管線，不是完整的知識庫。放大五倍的實驗我做過，量到什麼寫在 `07-scale-test.md`——那批資料我**沒有留**，因為留下來會讓剛完成的 58 題評分立刻失效。」 |
| 「為什麼不用 LangChain / LlamaIndex？」 | 「每個階段我都要能單獨測、單獨換。421 個測試在離線守衛下跑，CI 不需要模型也不需要連外——框架把這件事變難。」 |

## 5. Demo 前 30 分鐘的檢查清單

1. `ollama list` — 確認 `bge-m3:latest` 與 `qwen2.5-coder:14b` 都在
2. 重建資料集（README 的五道指令），確認 `make:pack` 的 hash 仍是 `5c49fb1e6fc577c1`
3. `npm start`，開 `http://127.0.0.1:3000/health`，確認 `dataset.state: ready`、`index.verified: true`
4. 把 §1 的五題各打一次，確認狀態與引用符合表格
5. `npm run check` — 421 tests

第 2 步 hash 對不上就停下來查，不要帶著不確定的資料集上場。

## 6. 不要現場打的問題

**「5.3版本更新了哪些內容？」以及任何 5.1–5.5 的版本總覽。**

目前語料裡沒有這些版本（會拒答，看起來像系統壞了）；而把它們加回來之後，答案開頭會變成
瑣事——已知缺陷，量測與成因寫在
[`08-version-section-shapes.md`](08-version-section-shapes.md)，追蹤在 #83。

如果對方主動問到版本總覽在更大語料上的表現，**直接承認並拿出那份文件**：
「這個我量過，兩個壞答案的開頭都出自公告的『調整及改善』章節，修法是依標題排重要性。」
主動端出來比被抓到好，而且那份文件本身就是答案。
